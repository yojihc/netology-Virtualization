## Задача 2

Выберите один из вариантов платформы в зависимости от задачи. Здесь нет однозначно верного ответа так как все зависит от конкретных условий: финансирование, компетенции специалистов, удобство использования, надежность, требования ИБ и законодательства, фазы луны.

Тип платформы:

- физические сервера;
- паравиртуализация;
- виртуализация уровня ОС;

Задачи:

- высоконагруженная база данных MySql, критичная к отказу;
- различные web-приложения;
- Windows-системы для использования бухгалтерским отделом;
- системы, выполняющие высокопроизводительные расчёты на GPU.

Объясните критерии выбора платформы в каждом случае.

#### Ответ:

1. Высоконагруженная база данных MySQL, критичная к отказу

Рекомендуемая платформа: Физические сервера

Критерии выбора:

Производительность дисковой системы - прямой доступ к NVMe/SAS дискам без накладных расходов виртуализации
Предсказуемость производительности - отсутствие "шумных соседей"
Низкая задержка - критично для транзакционных операций
Надёжность - возможность построения отказоустойчивых кластеров
Восстановление после сбоев - прямое управление оборудованием
Архитектура решения:

Кластер физических серверов с репликацией
RAID-массивы для отказоустойчивости дисков
Резервные каналы сети

2. Различные web-приложения

Рекомендуемая платформа: Виртуализация уровня ОС (контейнеры)

Критерии выбора:

Гибкость масштабирования - быстрое развёртывание и репликация
Эффективность использования ресурсов - минимальные накладные расходы
Быстрое развёртывание - CI/CD пайплайны
Изоляция окружений - dev/stage/prod
Экономическая эффективность - высокая плотность размещения
Технологии:

Docker + Kubernetes
Быстрое масштабирование под нагрузкой
Простое обновление без простоя

3. Windows-системы для бухгалтерского отдела

Рекомендуемая платформа: Паравиртуализация

Критерии выбора:

Изоляция окружений - каждая система в отдельной VM
Совместимость - полная поддержка Windows и периферии
Безопасность - изоляция критичных финансовых данных
Резервное копирование - снэпшоты всей системы
Лицензирование - соответствие требованиям Microsoft
Простота управления - знакомый IT-администраторам подход
Решение:

Hyper-V, VMware или KVM с Windows гостями
Централизованное управление
Быстрое восстановление из бэкапов

4. Системы для высокопроизводительных расчётов на GPU

Рекомендуемая платформа: Физические сервера

Критерии выбора:

Прямой доступ к GPU - минимальные задержки, полный контроль
Максимальная производительность - отсутствие накладных расходов виртуализации
Специализированные драйверы - прямой доступ к оборудованию
Эффективное охлаждение - критично для GPU
Пропускная способность - прямая работа с PCIe шиной
Особенности:

Серверы с множественными GPU (NVIDIA Tesla, AMD Instinct)
Высокоскоростная сеть (InfiniBand)
Специализированные системы охлаждения


## Задача 3

Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:

1. 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.

VMware vSphere Suite

2. Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.

Proxmox VE или oVirt - более корпоративный, но сложнее в настройке

3. Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.

Hyper-V Server 

4. Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.

Virtualbox 

## Задача 4

Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?

#### Ответ:

Я бы не создавал гетерогенную среду "с нуля", если нет веских технических или бизнес-причин.
Наилучшим решением будет  выбрать основную платформу, покрывающую 80% потребностей, и добавлять специализированные решения только там, где это действительно необходимо.
Гетерогенность должна быть обоснованной стратегией, а не случайным результатом технических решений.
